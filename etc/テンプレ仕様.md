# JSONデータフォーマット仕様書

## 1. 目的

本仕様は、アプリケーション設定情報を保持する JSON データフォーマットを定義する。
本フォーマットを用いることで、設定ファイルの構造、各項目の意味、許可される値、およびエラー判定条件を統一し、実装者ごとの差異を防ぐことを目的とする。

---

## 2. 適用範囲

本仕様は、設定ファイルとして読み込まれる JSON データに適用する。
対象は以下の情報を含む。

* フォーマットバージョン
* アプリケーション名
* 実行モード
* ログ出力設定
* 入力ファイルパス一覧

---

## 3. 全体構造

トップレベルは JSON object とし、以下のキーを持つ。

* format_version
* application
* mode
* logging
* input_files

全体構造の例を以下に示す。

```json
{
  "format_version": "1.0",
  "application": "SampleTool",
  "mode": "production",
  "logging": {
    "level": "INFO",
    "output_path": "logs/app.log"
  },
  "input_files": [
    "data/input1.csv",
    "data/input2.csv"
  ]
}
```

---

## 4. 項目定義

### 4.1 トップレベル項目一覧

| JSONパス | 型 | 必須/任意 | 説明 | 制約 | 例 | 備考 |
|---|---|---|---|---|---|---|
| format_version | string | 必須 | フォーマットのバージョンを示す | "1.0" 固定 | "1.0" | 非対応バージョンはエラー |
| application | string | 必須 | アプリケーション名 | 空文字不可、最大64文字 | "SampleTool" | 英数字、_、- を推奨 |
| mode | string | 必須 | 実行モード | "development"、"test"、"production" のいずれか | "production" | 大文字小文字を区別する |
| logging | object | 必須 | ログ出力設定 | null不可 | { "level": "INFO", "output_path": "logs/app.log" } | 配下の詳細は 4.2 を参照 |
| input_files | array | 必須 | 入力ファイルパス一覧 | 1件以上必須、各要素は空文字不可 | ["data/input1.csv"] | 配列順は処理順を表す |

---

### 4.2 logging 配下項目一覧

| JSONパス | 型 | 必須/任意 | 説明 | 制約 | 例 | 備考 |
|---|---|---|---|---|---|---|
| logging.level | string | 必須 | ログ出力レベル | "DEBUG"、"INFO"、"WARN"、"ERROR" のいずれか | "INFO" | 大文字固定 |
| logging.output_path | string | 必須 | ログ出力先ファイルパス | 空文字不可 | "logs/app.log" | 相対パス、絶対パスのどちらも可 |

---

## 5. 各項目の詳細仕様

### 5.1 format_version

format_version は、本 JSON データがどのバージョンのフォーマットに従っているかを示す文字列である。
本仕様では "1.0" のみを許可する。

#### ルール

* 必須項目とする
* 文字列型とする
* 値は "1.0" 固定とする
* "1.0" 以外の値はエラーとする

---

### 5.2 application

application は対象アプリケーション名を示す文字列である。

#### ルール

* 必須項目とする
* 文字列型とする
* 空文字は許可しない
* 最大文字数は 64 文字とする

---

### 5.3 mode

mode は実行モードを示す文字列である。

#### ルール

* 必須項目とする
* 文字列型とする
* 許可値は以下のいずれかとする
    * "development"
    * "test"
    * "production"
* 上記以外の値はエラーとする

---

### 5.4 logging

logging はログ出力設定を示す object である。

#### ルール

* 必須項目とする
* object 型とする
* null は許可しない
* 配下には level および output_path を持つこと

---

### 5.5 logging.level

logging.level はログ出力の詳細度を示す文字列である。

#### ルール

* 必須項目とする
* 文字列型とする
* 許可値は以下のいずれかとする
    * "DEBUG"
    * "INFO"
    * "WARN"
    * "ERROR"
* 上記以外の値はエラーとする

---

### 5.6 logging.output_path

logging.output_path はログ出力先ファイルパスを示す文字列である。

#### ルール

* 必須項目とする
* 文字列型とする
* 空文字は許可しない

---

### 5.7 input_files

input_files は入力ファイルパスの一覧を示す配列である。

#### ルール

* 必須項目とする
* 配列型とする
* 配列要素は文字列型とする
* 配列要素数は 1 件以上とする
* 各要素に空文字は許可しない
* 配列順は処理順として扱う

---

## 6. 共通制約

本フォーマット全体に対して、以下の共通制約を適用する。

* JSON 文字コードは UTF-8 とする
* トップレベルの未定義キーは許可しない
* logging 配下の未定義キーは許可しない
* 必須項目が欠如している場合はエラーとする
* 型が一致しない場合はエラーとする
* null は、明示的に許可された項目以外では禁止とする
* 文字列の前後空白は、読み込み側で自動除去しないものとする

---

## 7. エラー判定条件

以下のいずれかに該当する場合、本 JSON データは不正とみなし、読み込み処理を失敗とする。

### 7.1 必須項目欠如

例:

* format_version が存在しない
* logging.level が存在しない

### 7.2 型不一致

例:

* input_files が配列ではなく文字列である
* logging が object ではなく null である

### 7.3 許可値違反

例:

* mode に "release" が設定されている
* logging.level に "TRACE" が設定されている

### 7.4 制約違反

例:

* application が空文字
* input_files が空配列

### 7.5 未定義キーの存在

例:

* トップレベルに extra_setting が存在する
* logging 配下に rotate が存在する

### 7.6 非対応フォーマットバージョン

例:

* format_version が "2.0" である

---

## 8. 読み込み時の動作

読み込み処理は以下の手順で実施する。

1. JSON として妥当であることを確認する
2. トップレベル構造が object であることを確認する
3. 必須項目の存在を確認する
4. 各項目の型を確認する
5. 各項目の制約を確認する
6. 未定義キーの有無を確認する
7. すべて正常である場合に限り設定として採用する

いずれかの確認で不正を検知した場合、読み込み処理は失敗とする。

## 9. 正常例

```json
{
  "format_version": "1.0",
  "application": "SampleTool",
  "mode": "production",
  "logging": {
    "level": "INFO",
    "output_path": "logs/app.log"
  },
  "input_files": [
    "data/input1.csv",
    "data/input2.csv"
  ]
}
```

---

## 10. 異常例

### 10.1 format_version が不正な例

```json
{
  "format_version": "2.0",
  "application": "SampleTool",
  "mode": "production",
  "logging": {
    "level": "INFO",
    "output_path": "logs/app.log"
  },
  "input_files": [
    "data/input1.csv"
  ]
}
```

不正理由:

* format_version は "1.0" 固定であり、"2.0" は許可しない

---

### 10.2 input_files の型が不正な例

```json
{
  "format_version": "1.0",
  "application": "SampleTool",
  "mode": "production",
  "logging": {
    "level": "INFO",
    "output_path": "logs/app.log"
  },
  "input_files": "data/input1.csv"
}
```

不正理由:

* input_files は array<string> でなければならない

---

### 10.3 未定義キーを含む例

```json
{
  "format_version": "1.0",
  "application": "SampleTool",
  "mode": "production",
  "logging": {
    "level": "INFO",
    "output_path": "logs/app.log",
    "rotate": true
  },
  "input_files": [
    "data/input1.csv"
  ]
}
```

不正理由:

* logging.rotate は本仕様で未定義であり、許可しない

---

## 11. 拡張方針

本仕様の拡張は format_version を更新したうえで行う。
既存バージョンとの互換性が失われる変更を行う場合は、別バージョンとして定義すること。

#### 拡張例

* 新しいトップレベルキーの追加
* logging 配下への新項目追加
* 許可値の追加

#### 注意

* 既存実装との互換性を維持する必要がある場合は、未定義キー許可方針の見直しが必要となる
* 本仕様 1.0 では未定義キーを許可しない
