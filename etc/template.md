
# 構造体パラメータ変更時の影響範囲・データフロー調査

## 1. 目的

本資料は、構造体群のパラメータ変更テストを実施する前に、  
各パラメータを変更した際の影響範囲とデータフローを整理することを目的とする。

確認したい観点は以下の通り。

- どのパラメータを変更すると、どの中間データ・最終入力に反映されるか
- どの計算、分岐、出力に影響するか
- 値がどの関数を通って最終利用箇所まで到達するか
- 未使用、影響不明、DLL 内未確認の項目は何か

### 2.2 優先的にテストすべきパラメータ

| パラメータ | 理由 | 優先度 |
|---|---|---|
| 例: mode | 実行経路の分岐に関与 | 高 |
| 例: threshold | 判定条件に直結 | 高 |
| 例: gain | 出力計算値に影響 | 高 |

### 2.3 特記事項

- `#ifdef` により実行経路が切り替わる箇所がある
- 関数ポインタ経由で DLL 呼び出しが行われる箇所がある
- DLL 内部実装は一部未確認のため、最終利用箇所が不明な項目がある

## 3. 調査対象

### 3.1 対象構造体

| 構造体名 | 役割 | 備考 |
|---|---|---|
| 例: SourceConfig | 元入力パラメータ保持 | テスト変更対象 |
| 例: WorkParam | 中間変換用 | 内部処理用 |
| 例: DispatchInput | 最終入力 | DLL / ローカル処理へ渡される |

### 3.2 対象範囲

- 元構造体
- 中間構造体
- 関数ポインタ呼び出し箇所
- 条件コンパイル分岐
- 最終利用箇所
- DLL 呼び出し直前まで
- DLL 内部実装（確認できた範囲のみ）

## 4. 全体フロー概要

### 4.1 概要図

```text
元構造体
  ↓
中間構造体A
  ↓
中間構造体B
  ↓
関数ポインタ / 条件コンパイル分岐
  ↓
DLL またはローカル処理
  ↓
最終計算 / 判定 / 出力

4.2 概要説明
	•	元構造体の値は複数の関数を経由して中間構造体へ設定される
	•	最終的に、ローカル処理または DLL 呼び出し用の構造体へ詰め替えられる
	•	一部パラメータは途中で名称変更される
	•	一部パラメータは最終到達確認済みだが、DLL 内利用は未確認

この章では、「どういう関数を通って値がセットされ、最終利用箇所まで到達するか」を記載する。
重要パラメータを優先して整理する。

⸻

6.1 パラメータ: mode

6.1.1 概要
mode は、最終的に実行経路の切り替えに関与するパラメータである。

6.1.2 データフロー
	1.	SourceConfig.mode
	2.	build_work_param() で WorkParam.mode に設定
	3.	build_dispatch_input() で DispatchInput.mode に設定
	4.	dispatch_execute() を経由
	5.	#ifdef により DLL 経路またはローカル経路へ分岐
	6.	最終的に分岐条件または DLL 入力として使用

6.1.3 関連関数

順序	関数名	役割
1	build_work_param()	元構造体から中間構造体へ設定
2	build_dispatch_input()	最終入力構造体へ設定
3	dispatch_execute()	実行経路の分岐
4	execute_local() / execute_dll()	最終利用箇所

6.1.4 代入・変換内容

代入元	代入先	備考
SourceConfig.mode	WorkParam.mode	名称変更なし
WorkParam.mode	DispatchInput.mode	最終入力へ設定

6.1.5 最終利用箇所
	•	ローカル処理時: execute_local() 内の分岐条件
	•	DLL 経路時: DLL 入力構造体メンバーとして渡される
	•	DLL 内部利用: 未確認 / 確認済み

6.1.6 テスト観点
	•	値ごとに実行経路が変わるか
	•	ローカル経路と DLL 経路で挙動差があるか
	•	出力値だけでなく通過関数も確認する

⸻

6.2 パラメータ: threshold

6.2.1 概要
threshold は、最終判定条件に使われる閾値パラメータである。

6.2.2 データフロー
	1.	SourceConfig.threshold
	2.	build_work_param() で WorkParam.limit に設定
	3.	build_dispatch_input() で DispatchInput.limit に設定
	4.	execute_calc() を経由
	5.	judge_result() で比較条件に使用

6.2.3 関連関数

順序	関数名	役割
1	build_work_param()	中間値設定
2	build_dispatch_input()	最終入力設定
3	execute_calc()	計算実行
4	judge_result()	判定

6.2.4 代入・変換内容

代入元	代入先	備考
SourceConfig.threshold	WorkParam.limit	名称変更あり
WorkParam.limit	DispatchInput.limit	名称維持

6.2.5 最終利用箇所
	•	judge_result() における比較条件
	•	DLL 経路時は DLL 入力構造体に設定
	•	DLL 内比較利用は未確認 / 確認済み

6.2.6 テスト観点
	•	境界値前後で判定が変化するか
	•	閾値変更が出力件数にどう影響するか

9. テスト設計への反映

9.1 優先テスト対象

パラメータ	理由	テスト内容
mode	経路切替に関与	値ごとの経路確認
threshold	判定条件に直結	境界値テスト
gain	計算出力に影響	感度テスト

9.2 テスト時の観点
	•	出力値だけでなく、通過経路も確認する
	•	#ifdef 有効/無効の構成差を意識する
	•	DLL 経路では入力構造体の内容を必ず記録する
	•	未確認項目は期待値固定ではなく観察項目として扱う
