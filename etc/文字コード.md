

JSON文字コードに関する仕様

本システムで扱うJSONファイルの文字コードは、UTF-8 とする。
Shift_JIS などの他の文字コードは対象外とする。

採用理由

JSONの標準仕様である RFC 8259 では、相互運用性の観点から、ネットワーク越しにやり取りされる JSON テキストは UTF-8 でエンコードすることが求められている。RFC 8259 は、過去の仕様では UTF-8 が必須ではなかった一方で、実際には UTF-8 が事実上の標準となっており、相互運用性を実現できる唯一の文字コードであると説明している。  ￼

また、ECMA-404 でも JSON は Unicode のコードポイント列として定義されており、JSON の構文自体が Unicode を前提としている。UTF-8 は Unicode を表現するための標準的な方式であり、JSON の保存形式として最も適している。  ￼

運用方針

JSONファイルの保存・読込・受渡しは UTF-8 で統一する。
外部システムとの連携上、Shift_JIS など別の文字コードが必要な場合は、JSONそのものを Shift_JIS で扱うのではなく、入出力境界で変換する。

補足

日本語、全角記号、# を含むパス文字列をJSON内で扱う場合でも、UTF-8 を使用することで文字化けや文字コード不一致のリスクを低減できる。
一方、Shift_JIS は古いWindows系資産との互換性のために使われることはあるが、JSONの標準的な運用としては推奨されない。RFC 8259 でも、UTF-8 が相互運用性を達成する唯一の実用的な選択肢であると説明されている。  ￼
